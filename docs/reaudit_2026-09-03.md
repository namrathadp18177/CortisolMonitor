## New, concrete bug found during this re-audit (not in the original report)

**`OutputBluetooth.java` line 2255** reads `getIntent().getStringExtra("userrole")` — no underscore — while every other call site in the app (a dozen+ of them) uses `"user_role"`. This is the very last step of a biomarker test (`autoFinalizeAndShow`, right after the cortisol value is computed), so `role` is always `null` there regardless of who's actually running the test, and that `null` gets passed into `ResultActivity`. I traced the patient-*email* handling on this same path and it's correct — this typo only breaks the role flag, not who the result is attributed to. Low severity, one-line fix (`"userrole"` → `"user_role"`), but worth doing since it's the exact kind of loose-string-extra bug the original report was warning about.
